# 17 · 从学会原理，到可复现的项目

实验卡、模型卡与进入安全后训练的准备。

建议学习时间：30 分钟（含阅读与练习，按个人基础调整）。

前置章节：07、09、14、15。

## 学习目标

- 组织一个可复现的 GitHub 项目
- 为第二阶段写完整实验计划
- 用真实证据表达项目价值

## 一个结果需要哪些伴随材料？

代码负责定义方法，配置负责说明具体运行，manifest 记录模型、数据与依赖版本，日志与原始输出支持复算。报告把问题、选择和结果连接起来。别人应该能从一个命令找到运行所需条件，而不是猜测你用过哪个 checkpoint。

建议分开课程、教学数值实验、真实训练、评测和报告。本学习站中的交互数字是教学计算，不是安全后训练成绩。后续真正训练时，应保存每个阶段输出和失败案例，避免只保留最好的一张图。

## 实验卡要在运行之前写

记录假设、起始模型、训练数据、优化目标、超参搜索预算、主要指标、容忍范围、评测协议与停止条件。例如比较标准 DPO 与边界偏好 DPO 时，应控制起点和 token 预算，并加入 chosen-only SFT 和随机扩充对照。

训练日志解释过程，独立评测支持结论。负结果也要写：是奖励失效、数据不足、统计不确定，还是假设本身未得到支持？诚实区分“没有发现改善”和“证明没有改善”。

## 部署也是实验的一部分

导出适配器或合并权重后，核对底模、tokenizer、模板、精度和解码设置。用固定样例回归训练前后的关键行为；若推理框架或量化方式变化，再检查安全和正常任务分数。

模型卡描述用途、训练来源、评测、资源和局限；数据卡描述许可、标注、分布和切分。不要把许可证不允许再分发的权重或个人敏感数据放进仓库。大型制品通过可追溯下载路径提供。

## 第一阶段的毕业练习

不用 GPU 也可以完成准备：手算并运行 CE、奖励模型、DPO、PPO surrogate 和 GRPO 优势；解释每个输入、公式假设和常见故障。随后为安全后训练写数据规范、训练路线、评测矩阵和成本预估。

如果具备算力，再按最小 batch 验证 SFT 与 DPO 的保存/加载流程，在线 RL 先用可验证小任务。没有运行真实模型，就标记“设计/教学验证”，不把模拟器输出写成真实模型实验成绩。

## 把项目讲成可追问的证据链

十分钟讲解可以依次回答：解决什么问题，为什么选这个方法，数据怎样构建，对照是否公平，结果有多稳，失败在哪里，花了多少成本。简历只写能够回到日志、配置与报告核验的数字。

完成所有章节不是终点：保存你的错题、笔记和仍不确定的问题。进入第二阶段时，首先冻结一个主模型和评测协议，再实施安全 SFT、偏好优化、受控迭代及独立验证。

## 常见误区

“实现了公式”与“训练了真实语言模型”是不同成果；教学模拟、预实验和正式实验必须清晰区分。

## 检查理解

1. 下面哪条适合写进尚未训练模型的项目说明？

   - A. 模型安全性提升 50%
   - B. 完成 DPO 数值实现与教学验证
   - C. 已达到行业最优

   答案：B。已完成的代码与教学验证可以核验；未进行的训练不能编造成绩。

2. 为了复现一次训练，哪组材料最完整？

   - A. 仅最终权重
   - B. 代码版本、配置、数据/模型版本、环境、日志与运行命令
   - C. 只提供一张结果图

   答案：B。复现需要知道方法、输入、执行条件和结果来源。
