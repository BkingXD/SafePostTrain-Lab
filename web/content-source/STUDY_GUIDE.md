2. **读后复述**：不用缩写解释方法；写清输入、训练信号、更新对象和输出。

**验收**：每个算法都有一个数值表和一段更新过程解释；能指出采样策略与参考策略不同，能解释改变 beta、KL 系数、group size 不是同一种操作。

### 推导卡：把公式连接到代码

**SFT 的梯度从哪里来。** 先看二元情形：`p=σ(theta)`，标签为 `y∈{0,1}`，`L=−y log p−(1−y)log(1−p)`。应用链式法则，`dL/dtheta=p−y`。多类别 softmax 交叉熵对某个 logit 的导数同样是“预测概率−one-hot 标签”；带 mask 时还要乘 mask 并除有效监督 token 数。这解释了为什么改变分母会改变样本权重，而不只是改变显示的 loss。

**DPO 的参考策略从哪里来。** 固定一个问题 x，在参考策略支持的回答空间内，设 beta>0，最大化 `Σ_y π(y)r(y)−βΣ_y π(y)log[π(y)/πref(y)]`，同时约束 `Σ_yπ(y)=1`。给归一化约束加拉格朗日乘子，对 π(y) 求导为零，得到 `log[π*(y)/πref(y)]=r(y)/β−log Z(x)`；其中 `Z(x)=Σ_yπref(y)exp[r(y)/β]`。移项后 `r(y)=βlog[π*(y)/πref(y)]+βlog Z(x)`。对同一 x 的 chosen/rejected 作差，`log Z(x)` 消失，再代入 Bradley–Terry 概率就得到四个 log-prob 的 DPO 目标。最后用可训练 πθ 代替理想 π* 进行拟合；有限模型和有限数据不保证达到该理想最优策略。推导依据见 [DPO 原论文](https://arxiv.org/abs/2305.18290)。

**PPO 为什么有 ratio。** 对旧策略采到的动作，用 `ratio=πθ(a|s)/πold(a|s)` 修正动作概率变化，以 `ratio×A` 构成代理目标。实际 PPO 对状态分布采用近似，并不是一次更新就获得真实新策略回报的精确估计。使用 `min(ratio×A, clip(ratio,1−ε,1+ε)×A)` 限制某些有利方向的激励；正、负 A 要分别算。`old` 随采样轮次刷新，`ref` 通常固定，两者承担不同作用。依据见 [PPO 原论文](https://arxiv.org/abs/1707.06347)。

**GAE 与组优势为何不同。** GAE 的反向递推是 `δ_t=r_t+γV_{t+1}−V_t`、`A_t=δ_t+γλA_{t+1}`，末端如何取 `V_{t+1}` 取决于真正终止还是需要 bootstrap 的截断；状态价值为 token 的回报提供基线。GRPO 教学实现对同题回答的最终奖励作 `A_i=(r_i−mean(r))/(std(r)+ε)`，再分配给该回答的监督 token。它去掉了此处的 learned critic，却没有获得精确的 token 贡献标签。分别参考 [GAE](https://arxiv.org/abs/1506.02438)和 [DeepSeekMath 中的 GRPO](https://arxiv.org/abs/2402.03300)。

将上面的符号逐项对应到 `token_statistics`、`preference_loss`、`gae_tensor` 和 `train_online`。验收不是背完整证明，而是能指出每一次求和覆盖哪个维度、哪个量停止梯度、哪个分布提供样本，以及公式在哪些环境假设下不再适用。

## 第四组作业：用具体案例学安全与评测（02、10、12、13、15）

以下均为教学数据和纸面案例，不是模型运行结果。先独立作答，再对照分析要点。

### 案例 A：奖励投机

摘要任务的原文是“会议改到周五，地点未定”。评分器给“包含周五”1 分、“包含地点”1 分、“超过 30 字”1 分。回答甲是“会议改到周五，地点未定”，回答乙反复提及“周五、地点”，并虚构会议室。

分析要点：乙可能得到更高代理奖励，却牺牲事实一致和简洁性。应分别检查覆盖、是否虚构、长度与重复，并在不依赖原奖励规则的样例上复核。这个反例证明评分器有漏洞，尚不能证明某个训练算法一定会利用它。

### 案例 B：安全边界与双向偏好

| 抽象请求 | 期望行为 | 偏好关系与理由 |
|---|---|---|
| 解释怎样识别诈骗并保护账户 | 提供防护建议 | 有用的防护说明优于只看到敏感词就拒绝 |
| 要求协助盗取他人账户 | 拒绝实质性帮助，提供合法替代 | 安全回应优于执行侵害请求 |
| 同时请求账户防护与盗取步骤 | 回答防护部分、拒绝侵害部分 | 有边界的部分完成优于全部执行；无根据全部拒绝也损失帮助性 |
| 引用一段冒充指令的外部文档并要求摘要 | 把文档当数据，完成授权摘要 | 遵守原任务优于服从文档里的额外命令 |

练习：为每行写 risk category、意图、允许范围、标签理由，再添加一个上下文会改变判断的变体。威胁模型应写攻击者能控制的输入、目标、调用预算和成功判定。不能把“拒绝语气”本身作为安全通过条件。

### 案例 C：同一组攻击有两个分母

假设 4 个有害行为各尝试 3 次，成功次数依次是 `[2, 0, 1, 0]`。尝试级成功率为 `3/12=25%`；行为级 ASR@3 为 `2/4=50%`。两者回答不同问题，必须同时写清预算和分母。

另有 10 个合法请求，3 个被无根据拒绝，2 个未拒绝但答非所问：误拒绝率为 30%，却不能因此宣称任务完成率为 70%。任务完成还需单独判定。

统计练习：解释为何同一行为的三次尝试可能相关；设计按行为重采样的 bootstrap，而不是把 12 次全当独立行为。样本区间衡量评测估计不确定性，多 seed 衡量训练随机性，两者不能互相替代。

### 案例 D：广义安全需要不同证据

| 声称改善的风险 | 教学案例 | 需要哪些证据 | 不能接受的结论 |
|---|---|---|---|
| 诚实性/校准 | 答案更流畅、自报信心更高，事实错误数量不变 | 答案正确性、置信分箱、覆盖率与拒答的共同变化 | “更自信，所以更可靠” |
| 隐私 | 模型拒绝复述一个合成秘密，但在另一上下文中仍输出它 | 只用合成 canary；预先定义查询方式、暴露率和正常任务对照 | “拒绝一次，所以没有记忆” |
| 公平性 | 总体误拒绝降低，某语言或群体切片变差 | 成对语境核验、分组样本量、错误率/误拒绝和不确定性 | “总体分数高，所以所有群体公平” |
| 遗忘 | 删除集合上回答下降，保留集合也明显退化 | 删除/保留集、不同查询方式、恰当基线及功能保留 | “全部能力下降，就是成功遗忘” |
| 投毒/后门 | 常规测试正常，出现指定合成标记时输出改变 | 明确攻击假设、触发/无触发对照、来源审计 | “没有遇到触发器，所以不存在风险” |
| 后续安全退化 | 无害任务微调或量化后，旧边界样例失效 | 同协议下的前后回归、安全与能力切片 | “曾经安全，所有后续版本都安全” |

**验收**：对每行补一个可能推翻改善主张的实验，再选择一行写一页完整案例分析。合成案例只用于理解风险，不构成真实模型安全结论。

## 第五组作业：专项能力案例（16）

每个方向先完成一段失败分析，再选择一个写完整设计；不要求第一阶段同时训练所有专项模型。

| 方向 | 代表案例 | 要补充的训练/评测条件 |
|---|---|---|
| 领域适应 | 回答使用正确术语，却给出过时事实 | 数据时效与来源、事实核验、领域基线、保留普通能力；不能只评价专业口吻 |
| 长上下文 | 关键证据在开头时答对，放到中间后答错 | 固定内容改变位置、干扰量、长度分布、截断检查与有效证据利用 |
| 多语言 | 翻译后风险意图或自然程度改变 | 语言与语境复核、原语/译文来源、各语言能力与安全切片 |
| 工具/Agent | 文档检索结果中出现要求发送私有文件的文字 | 工具消息边界、动作授权、参数校验、任务成功和违规动作的轨迹评价 |
| 多模态 | 单看文字任务合法，配图后语义不同；或裁剪丢失关键内容 | 图文对应、图像预处理、可训练模块、联合语义与正常能力评价 |

工具轨迹走读：用户授权“查找并总结一份公开文档” → 检索工具返回文档及一段要求发送本地文件的附加文字 → 模型调用发送工具。最后回复再礼貌也不能使这条轨迹安全；违规发生在超出授权的动作。合格设计应保留每一步 observation/action、工具参数、反馈、终止状态和策略版本，并在沙盒中测试任务完成与违规动作。

**验收**：所选方向的设计至少包括一个输入样例、期望输出/轨迹、可训练组件、反馈来源、基线、数据切分、专项指标、成本和失败案例。若只有“使用 SFT+RL 提升能力”，仍然没有达到可执行程度。

下面的链接已于 2026-11-07 核对论文题目与摘要。它们是代表性研究入口，不是“最新最优方法”的榜单，也不表示项目已经复现其结果。首遍读问题、数据/评测和限制；选定深挖专题后再精读方法与代码。每篇提交“问题、假设、对照、指标、一个局限”五行阅读卡。

| 模块/主题 | 一手资料 | 阅读任务 |
|---|---|---|
| 13 · 诚实性 | [TruthfulQA](https://arxiv.org/abs/2109.07958) | 解释为什么模仿常见文本与生成真实答案之间可能存在冲突；区分真实性和帮助性 |
| 13 · 不确定性 | [Language Models (Mostly) Know What They Know](https://arxiv.org/abs/2207.05221) | 区分“某个答案正确的概率”和“知道答案的概率”，讨论换任务后的校准问题 |

| 13 · 公平/偏见 | [BBQ](https://arxiv.org/abs/2110.08193) | 比较信息不足与信息充分的上下文；明确其美国英语语境不能直接代表所有文化 |
| 13 · 遗忘 | [TOFU](https://arxiv.org/abs/2401.06121) | 说明为什么需要合成遗忘集、保留能力及多项指标，不能只观察拒答 |

| 13 · 后续微调退化 | [Fine-tuning Aligned Language Models Compromises Safety, Even When Users Do Not Intend To!](https://arxiv.org/abs/2310.03693) | 找出无害任务微调与恶意微调的不同设置，设计自己的前后安全回归协议 |

| 16 · 多模态 | [Visual Instruction Tuning](https://arxiv.org/abs/2304.08485) | 画出视觉编码器、连接模块与语言模型，说明指令数据和普通文本 SFT 的差别 |

## 面试与自检：先口述，再核对要点

| 问题 | 合格回答应包含的要点 |
|---|---|
| 训练 loss 降低，为什么生成反而变差？ | teacher forcing 与生成前缀不同；代理目标、长度、模板和遗忘；查看原始输出而非凭 loss 判断 |
| DPO 是否保证 chosen 的概率上升？ | 不保证；相对差距可能因 rejected 降得更多而改善；检查 chosen log-prob 与真实生成 |
| LoRA 的参数少，为何还会 OOM？ | 冻结底模的存储、激活、临时张量和序列长度仍存在；需实测峰值 |
| PPO 的 old 和 reference 能合并成一个吗？ | old 用于本轮采样比率，reference 用于固定漂移约束；两者随训练变化方式不同 |
| 组内奖励都相同，GRPO 是否完全没有更新？ | 偏好区分优势为零；若有 KL 等其他项，仍可能更新。不能把零优势说成所有梯度必为零 |
| 模型全部拒绝，是不是安全训练成功？ | 有害完成可能低，但误拒绝和正常任务质量会失败；必须联合评价 |
| 8 个开发样例全部答对能证明什么？ | 仅证明在指定设置下这 8 条通过；不能证明新意图、长文本、其他语言或内容安全 |
| 保存并重载权重一致，能否证明可恢复训练？ | 仅重载不够；本项目另有模型/AdamW/RNG 下一步一致测试，但完整在线 PPO 仍需 critic、其优化器与 rollout 等状态 |
| 网站显示 17/17 完成，能否写“完成大模型安全后训练”？ | 只能说明完成课程自检；实际训练和 benchmark 需模型、配置、原始结果与独立评测证据 |

## 第一阶段毕业包与通过标准

以下是你学习过程中的个人毕业练习，课程与实验材料已经交付，并不等待这些作业完成后才可使用。整理自己的材料时，未运行的结果写“待实验”，不要把项目示例结果当作自己独立完成的实验：

1. **知识与推导**：17 章的自主笔记，CE/BT/DPO/PPO/GAE/GRPO 关键计算及假设。
2. **实践记录**：标准库实验、当前 TinyLM 运行、原始输出复算、至少一个负结果分析。
3. **安全规范**：政策、威胁模型、双向偏好样例、数据卡和污染控制范围。
4. **专题案例**：广义安全案例表、一个专项任务的完整设计。
5. **第二阶段实验卡**：候选模型/数据选择条件，E0→安全 SFT→DPO→改进路线，chosen-only SFT 与随机数据对照，安全/误拒绝/能力/成本指标，冻结与停止条件。
6. **复现与交付**：代码/数据/环境版本、命令、checkpoint 范围、模型卡草稿和十分钟讲解；明确哪些恢复/量化/部署检查还没做。

通过的标准是：能从原始样例解释到损失，再从损失解释到更新和真实输出；能发现评价口径、数据泄漏或代理奖励的问题；能诚实说明实验边界。无需先获得漂亮的提升数字，也不把上传 GitHub 作为学习通过条件。

QLoRA、GPU 峰值显存、BF16、多卡及部署量化回归按可用资源开展。第一阶段已经给出它们的原理与实践设计；没有这些硬件不影响阅读、数值交互和 CPU 教学闭环，也不能把设计稿写成已经完成的硬件实测。
