# 01 · 从下一个词，到一个好助手

先把模型、概率和后训练放在同一张地图上。

建议学习时间：75 分钟（含阅读与练习，按个人基础调整）。

前置章节：无。

## 学习目标

- 解释 token、logit、softmax 和序列概率
- 区分预训练、持续预训练与后训练
- 说清楚训练和生成时分别发生了什么

## 模型究竟在预测什么？

想象一个反复练习补全句子的学生。语言模型看到前面的文字，为“接下来出现什么”分配概率。它处理的单位是 token：可能是一个词、一段汉字、标点或词的一部分。token 的边界由 tokenizer 决定，不能把一个 token 永远理解成一个字。

每一步模型输出一组未归一化分数，叫 logits。softmax 把它们变成总和为 1 的概率。选出一个 token 后把它接回上下文，再预测下一个。这样的自回归生成不会一次写完整个答案。Transformer 用注意力汇总上下文；因果掩码保证预测当前位置时看不到未来答案。

## 把一段回答拆成可计算的概率

用 x 表示问题，y₁…yₜ 表示回答。序列概率是每一步条件概率的乘积：P(y|x)=∏ₜP(yₜ|x,y<ₜ)。取对数后，乘法变成加法：log P(y|x)=Σₜ log P(yₜ|x,y<ₜ)。计算机通常累加 log-prob，避免很小的概率连乘后下溢。

教学例子：一个三 token 回答的条件概率依次为 0.5、0.25、0.8，序列概率为 0.1，对数概率约为 −2.303。注意每个数已经包含不同的前文条件，不是三个孤立词的频率。平均负对数似然约为 0.768；序列 log-prob 与平均 loss 的数值不同。

## 预训练之后为什么还需要训练？

预训练通过大量文本学习语言规律和知识，但“常见的续写”不一定是“用户需要的回答”。持续预训练常用领域文本继续训练语言建模能力。SFT 则展示问题与理想答案，让模型学习指令形式；偏好优化进一步告诉模型两个答案哪个更符合目标；在线强化学习利用当前策略生成的回答及反馈来更新。

这些阶段可以交替使用，并不是每个模型都必须依次经过所有算法。后训练既能改变风格和安全行为，也可能提升专项能力，但不保证无中生有地获得所有知识。RAG 是在输入中补充检索资料，系统提示是改变条件上下文，它们与更新模型权重是不同的操作。

## 温度改变采样，不改变权重

采样时可用 softmax(logits / T)。T 较小会使概率更集中，T 较大通常使分布更平。贪心解码直接选最大概率 token；温度为零一般通过贪心逻辑实现，不是把公式直接除以零。top-p 则保留累计概率达到阈值的一组候选。

在下方实验中调节温度，观察每个候选的概率和熵。熵衡量分布的不确定性，不等于回答质量。高温不能保证创造力，低温也不能保证事实正确。比较训练前后模型时必须固定这些生成设置，否则会把采样变化当成训练收益。

## 最少需要的数学：梯度与更新

loss 是我们希望减小的标量，梯度描述参数微小变化时 loss 怎样变化。最简单的更新是 θ←θ−η∇θL，其中 η 是学习率。负号表示朝下降方向走；学习率太大可能越过低点，太小则学习缓慢。反向传播利用链式法则，逐层计算每个参数对 loss 的影响。

以只有两个动作的模型为例，动作 1 的概率 p=σ(θ)。如果示范答案是动作 1，交叉熵 L=−log p 的导数为 p−1。θ=0 时 p=0.5，η=0.2，一次更新得到 θ=0.1，p 约为 0.525。优化器并没有把答案复制进一个槽位，而是改变了分布。Adam 在梯度之外维护一二阶移动统计来调节更新，权重衰减则是另一种正则化选择。

## 动手与自检

手算两段不同长度回答的 log-prob，再比较平均负对数似然。解释为什么较长回答的原始 log-prob 通常更负，以及为什么不能直接据此认为它质量更差。

面试练习：给出“改系统提示、加检索、更新 LoRA、提高温度”四种操作，说明哪一种会改变可训练参数。合格标准是同时解释输入、权重和采样三个层次。

## 技术拆解：从文本到一次参数更新

训练链路依次为原始消息 → 模板化文本 → token IDs 和 attention mask → 模型 logits[B,T,V] → 移位后的 labels[B,T] → loss → backward → optimizer.step。B 是批大小、T 是序列长度、V 是词表大小；对话角色不是模型天然理解的结构，必须由模型适配的 chat template 转为控制 token。

teacher forcing 会并行计算每个位置对下一 token 的预测，但每个位置仍只能读取左侧上下文。生成时则将新 token 逐个接回输入，常借助 KV cache 复用历史键和值。训练 loss 下降只说明拟合了所标记位置，不能单独证明任务成功或安全。

## 一条样本如何进入 loss

假设模板 token 为 [BOS, user, 问题, assistant, 答案1, 答案2, EOS]；若只监督助手回答，labels 中 prompt 部分设为 -100，答案和 EOS 保留。logits 在 assistant 位置预测答案1，而不是在答案1位置预测答案1。框架内部可能已经执行 shift，手动再 shift 会错位。

用 log_softmax 后 gather 正确 token 的 log 概率，再在有效标签上求平均；有效 token 为零的批次应拒绝，不要用一个虚假的 0 loss 掩盖数据问题。相同模板与 decode 参数下保存一次训练前生成结果，才可比较训练后的行为变化。

## 论文阅读与实操

先读 2025 年后训练综述的阶段划分，再读 Qwen3 技术报告中 thinking/non-thinking 和多阶段后训练；将模型发布方的说法与本地实验分开。请画一张张量形状图，并在 GPU 实战的 mask 表中逐个指出被监督的位置。

思考题：同样的模型、相同问题，改变系统提示、检索片段、采样温度、LoRA 权重各改变哪一层？请分别说明输入上下文、解码策略和参数状态；如果只观察最终文本，如何设计对照识别来源？

## 算例：损失、梯度与更新方向

设一个二分类 token 的目标概率是 p=0.25，交叉熵 L=−log(p)≈1.386。若目标 token 的 logit 为 z，softmax 交叉熵对该 logit 的导数为 p−1=−0.75；小步梯度下降会提高 z，从而通常提高目标概率。批次计算应明确对样本还是有效 token 求平均。

这个结论只说明一步局部更新方向。多层网络、Adam 状态、权重衰减和其他样本梯度会改变实际结果；预先计算的 loss 下降不保证生成回答正确。用自动求导和有限差分比较一个参数的小扰动，可验证梯度实现。

## 检查清单：训练与解码

训练检查 tokenizer、special tokens、attention mask、标签、loss 的分母、梯度和 optimizer；生成检查模板、停止 token、最大长度、temperature、top-p 与随机种子。比较两次生成时只改变一个因素；训练产物和推理配置都要记录。

## 常见误区

把“概率高”当成“事实正确”。模型概率反映当前模型在给定上下文下的分布，真实性需要额外验证。

## 检查理解

1. 三个 token 的条件概率为 0.5、0.25、0.8，序列概率是多少？

   - A. 0.1
   - B. 1.55
   - C. 0.517

   答案：A。按链式法则相乘：0.5 × 0.25 × 0.8 = 0.1；不能相加或取平均。

2. 只修改生成温度，会发生什么？

   - A. 更新模型参数
   - B. 改变输出采样分布
   - C. 自动提高事实准确率

   答案：B。温度影响 logits 转成采样概率的方式，并不执行反向传播。
