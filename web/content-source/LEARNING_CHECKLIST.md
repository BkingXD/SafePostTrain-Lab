# 第一阶段学习验收

本清单检查学习者是否理解核心知识，并能在 GPU 上完成教学训练闭环。网站的“完成章节”只表示答对该章的理解检查，不等于通过所有研究与工程能力验收。

## GPU 实战的设备要求

先运行 `python -m labs.tiny_lm.run --check-device`，再在 CUDA / FP32 环境完成训练。入口仅接受 `cuda` 或 `cuda:N`，不可用时失败。运行报告必须记录实际 GPU 设备、精度、环境和资源测量。BF16、QLoRA 和多卡只按实际实现与测试情况报告。

## 五条贯穿全程的要求

- 能用自己的话解释问题，而非仅复述缩写。
- 能手算一个最小例子，并与代码/交互结果核对。
- 能指出公式和教学模拟的假设。
- 能诊断至少一个常见失败。
- 能将方法与数据、评测和成本联系起来。

## 毕业练习：设计一套安全后训练实验

提交一个小型研究包，包含以下材料。没有可用 GPU 时将训练结果明确标为待实验。

1. **问题与假设**：明确提高哪种安全行为、控制哪些正常能力损失，以及什么结果会推翻假设。
2. **数据卡**：来源、许可、角色格式、边界样例、分组切分、去重与污染检查。
3. **训练路线**：原模型 → 安全 SFT → 标准 DPO → 改进；在线 RL 的加入理由与资源门槛。
4. **公平对照**：chosen-only SFT、随机新增数据、移除边界数据、回放比例。
5. **评价矩阵**：安全、误拒绝、正常能力、未见攻击与成本；固定裁判和解码设置。
6. **复现计划**：版本、配置、日志、原始回答、恢复和统计方法。
7. **预期失败**：至少三种失败机制及排查办法。

建议评分以解释与证据为主：概念正确 30%、计算/代码一致 25%、实验设计 25%、局限与复现 20%。这是学习建议，不是招聘或认证标准。
